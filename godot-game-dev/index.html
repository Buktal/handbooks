Godot 游戏开发入门指南

面向零基础读者的系统入门教程：从「游戏引擎是什么」讲起，到亲手完成一个具备完整玩法的小游戏——可玩、有计分、有胜负、有音效，并打包分发给其他人。不需要游戏开发经验，也不需要美术基础。

引擎完全免费且开源 跟随教程约需 3–4 小时 实战项目：《接金币》 支持导出 Windows / Android

游戏引擎概览第 1 章

游戏引擎是负责渲染、音频、物理、输入等基础功能的软件框架，开发者只需专注实现游戏规则本身。目前主流的几款引擎如下：

引擎特点适用场景
Unity生态规模最大，使用 C# 开发，行业招聘的主流选择3D 项目、以就业为目标的学习者
Godot免费开源，体积约 100 MB，对新手友好，2D 能力出色个人开发者、2D 项目、零成本起步
虚幻 5（Unreal）3A 级画面表现，使用 C++ 或蓝图可视化编程，硬件要求较高追求顶级画面表现的项目
Cocos国内微信、抖音小游戏生态的主流引擎目标明确面向手机小游戏平台
本指南自本章之后的所有内容，均以 Godot 为基础展开。对零基础读者而言，选择 Godot 的理由非常实际：完全免费且无隐性收费、软件轻量、自带脚本语言的语法接近 Python、2D 教学与免费素材生态完善。其他引擎各有优势，但在「第一次做游戏」这件事上，Godot 的综合门槛最低。

获取与安装 Godot第 2 章

下载页提供多个版本，选择正确的版本可以避免后续的一系列问题。

2.1 下载步骤

  1. 访问官方网站 godotengine.org，进入 Download 页面，选择 Windows 平台。
  2. 下载标准版（Standard），即约 100 MB 的 zip 压缩包。
  3. 将压缩包解压至任意目录（例如 D:\Godot），其中只包含一个 exe 文件。
  4. 双击运行。Godot 为绿色软件，无需安装。

四个核心概念第 4 章

Godot 的一切都建立在这四个概念之上。先用直观比喻建立理解，编写代码时自然会逐渐熟悉。

节点（Node）——最小的功能单元

一个完成特定工作的组件：一张图片（Sprite2D）、一段音频（AudioStreamPlayer）、一个计时器（Timer）。节点本身知道如何完成自己的工作，开发者负责安排它们的位置与连接方式。

场景（Scene）——节点的组合

将若干节点组装为一个有意义的整体（例如「一个敌人」= 图形 + 碰撞判定 + 行为脚本），保存为 .tscn 文件。场景可以无限复用：制作一个敌人场景后，即可生成任意数量相同的敌人。这是 Godot 组织项目的基本方式。

信号（Signal）——节点间的通知机制

当特定事件发生时（计时器到点、两个对象重叠、按钮被点击），节点会发出信号，所有监听该信号的代码将被自动执行。游戏中所有「A 发生了，因此 B 需要响应」的逻辑都由信号完成，节点之间无需相互引用。

脚本（Script）——行为的定义

用 GDScript 编写的、描述「该节点如何表现」的代码。GDScript 语法与 Python 非常接近，可读性强，是适合初学者的游戏脚本语言。

附：有编程基础读者的概念对照（选读）
已有概念Godot 中的对应
DOM / 组件树场景树（Scene Tree），一切皆节点
可复用组件场景（.tscn），可嵌套、可实例化

每帧回调_process(delta)，delta 为该帧耗时的秒数，位移计算应乘以它

最主要的思维转变：游戏不是「请求—响应」模型，而是一个每秒运行约 60 帧、所有对象常驻内存并持续相互影响的运行环境。每一帧的时间预算约为 16.6 毫秒。

实战起步：可控制的角色第 5 章

本章目标：创建项目，实现一个可以用方向键左右移动的角色。这个最小的例子将完整走通「输入 → 更新 → 渲染」的游戏主循环。

5.1 新建项目与第一个场景

  1. 在项目管理器中点击「+ 新建」，项目名称填写 catch_coin，点击创建并编辑。
  2. 左侧场景面板中点击「2D 场景」按钮，生成一个 Node2D 根节点（2D 世界的容器）。
  3. 按 Ctrl+S 保存，场景命名为 main.tscn。
右上角文件面板中出现 res://main.tscn（res:// 即项目根目录），即表示本节完成。

5.2 创建角色并编写第一段代码

  1. 点击场景面板左上角的「＋」按钮，搜索 Sprite2D 并添加。中间视口会出现一个白色方框，即角色的初始形态。
  2. 在视口中把白色方框拖到画面下方居中（新节点默认停在左上角原点）。第 6 章它会作为接取金币的「篮子」使用，位置从现在起就应摆放正确。
  3. 右键点击 Sprite2D，选择「附加脚本」，保持默认设置，点击创建。
  4. 将以下代码完整复制到脚本编辑器中（覆盖原有内容）：
extends Sprite2D
# extends 表示继承：本脚本挂载在 Sprite2D 节点上，为其定义行为。

# 引擎每帧调用一次，delta 为距上一帧经过的秒数
func _process(delta: float) -> void:
	# 读取输入：左右方向键，返回 -1 / 0 / 1
	var dir := Input.get_axis("move_left", "move_right")
	# 速度为每秒 300 像素。乘以 delta 保证在不同帧率下速度一致
	position.x += dir * 300.0 * delta
	# 限制在屏幕范围内（Godot 4 默认窗口宽度即 1152 像素，无需修改）
	position.x = clamp(position.x, 50, 1102)
  1. 还需要定义 move_left 与 move_right 这两个动作。注意：Godot 4 默认的输入映射里没有这两个动作（内置的 ui_left 等属于界面导航，不建议直接使用），需要手动添加：打开右上角「项目设置」→ 顶部「输入映射」标签 → 在「添加新动作」输入框中填写 move_left 并按回车 → 在列表中找到它，点击右侧「+」按钮 → 按下键盘左方向键 → 确认。再按同样步骤添加 move_right 并绑定右方向键。完成后关闭设置窗口。
  2. 保存场景与脚本（Ctrl+S），按 F6 运行当前场景。
运行后应看到：弹出游戏窗口，白色方框随左右方向键平滑移动，且不会移出屏幕。至此已完成游戏开发中第一个重要里程碑——主循环已经亲手实现，后续所有内容都是这一循环的扩展。

5.3 常见问题排查

症状原因解决方法
白色方框不移动动作名称未配置或拼写不一致检查输入映射中的名称与代码是否完全一致
报错「无效的动作名」未在输入映射中定义该动作返回上一步完成配置
窗口一闪而过脚本存在语法错误查看底部输出面板中的红色错误信息及行号。GDScript 对缩进敏感，全篇必须统一使用 Tab
移动速度时快时慢位移未乘以 delta检查代码中的 * delta

5.4 为角色指定图片素材

  1. 访问免费素材站点 kenney.nl/assets（详见第 9 章），下载任意素材包并解压。
  2. 将 png 图片直接拖入 Godot 右上角的文件面板（建议放入 assets 文件夹）。
  3. 选中角色的 Sprite2D 节点，在右侧检查器中找到 Texture 属性，将图片从文件面板拖入该属性槽。
  4. 图片过大时，在检查器 Transform → Scale 中改为 0.5, 0.5（等比缩小一半）。
角色显示为一张图片，且仍然可以用方向键控制移动，即表示本节完成。

实战进阶：完成《接金币》第 6 章

游戏规则：玩家控制一个篮子左右移动，屏幕上方不断落下金币与炸弹；接到金币得 1 分，碰到炸弹失去 1 条生命，3 条生命耗尽后游戏结束，按 R 键重新开始。本章结束后，你将得到一个完整可玩的游戏。

本章施工顺序：先做出金币与炸弹的可复用场景（6.1），再让它们持续生成（6.2），然后实现接取判定与计分（6.3），接着完成界面显示与重开闭环（6.4），最后添加音效（6.5）。每一节都可以运行验证，再进入下一节。

6.1 制作金币与炸弹——第一个可复用场景

  1. 点击场景面板顶部的「＋」新建场景。这次不选「2D 场景」（那样根节点是 Node2D），而是点击「其他（Other）」，在列表中选择 Area2D 作为根节点——因为金币本身就需要接触判定，直接让它做根。将根节点重命名为 Coin。
  2. 为根节点添加 Sprite2D 子节点，并指定金币图片。若素材包中没有金币、炸弹这类图案，用两张不同的图片区分即可（例如星星与方块）——本教程教的是机制，图片本身不影响学习。
  3. 再为根节点添加 CollisionShape2D 子节点（判定范围），在检查器的 Shape 属性中新建 RectangleShape2D，并在视口中拖出一个覆盖金币的矩形。若节点顶部出现黄色感叹号，表示未设置 Shape，必须完成设置。
  4. 为根节点附加脚本：
extends Area2D

func _ready() -> void:
	# 出生时随机确定下落速度（每秒 150~250 像素），保存在节点上
	set_meta("speed", randf_range(150.0, 250.0))
	set_process(false)  # 暂停更新，等待主场景通知开始

func start_falling() -> void:
	set_process(true)

func _process(delta: float) -> void:
	position.y += get_meta("speed") * delta
	# 落出屏幕底部后自我删除，防止对象持续累积
	if position.y > 700:
		queue_free()
  1. 按 Ctrl+S 保存为 coin.tscn。
  2. 按完全相同的步骤制作 bomb.tscn，将图片替换为炸弹素材。
  3. 为两者添加分组标识：选中场景根节点，点击检查器上方的「分组」按钮，金币场景添加组 coin，炸弹场景添加组 bomb。后续代码通过分组区分接触的对象。

6.2 实现生成器——让掉落物持续出现

切换回 main.tscn（通过场景面板顶部的标签页），为根节点 Node2D 附加脚本（本节先实现生成逻辑；6.4 将给出整合界面与游戏结束逻辑后的完整最终版，届时整体替换）：

extends Node2D

# preload 提前将场景文件加载进来（类似 import）
var coin_scene := preload("res://coin.tscn")
var bomb_scene := preload("res://bomb.tscn")

func _ready() -> void:
	# 创建一个计时器：每 0.8 秒触发一次生成
	var timer := Timer.new()
	timer.wait_time = 0.8
	timer.timeout.connect(_on_spawn)  # 到点发出信号，调用 _on_spawn
	add_child(timer)
	timer.start()

func _on_spawn() -> void:
	# 80% 概率生成金币，20% 概率生成炸弹
	var scene := coin_scene if randf() < 0.8 else bomb_scene
	var item := scene.instantiate()  # 从模板生成一个实例
	item.position = Vector2(randf_range(60.0, 1090.0), -30)  # 屏幕上方的随机位置
	add_child(item)  # 加入场景树后，它自动开始执行自己的下落逻辑
	item.start_falling()
按 F6 运行后应看到：金币与炸弹持续从屏幕上方生成并下落，落出屏幕后自行销毁，运行流畅。这里用到了两个核心模式：场景实例化（一个模板生成任意数量的实例）与信号连接（计时器到点触发函数）。

6.3 接触判定与计分

  1. 升级篮子结构：在 main.tscn 中新建一个 Area2D 节点，将现有的 Sprite2D 拖入其下作为子节点。注意：此时篮子可能会跳向画面左上角——因为新的 Area2D 位于坐标原点，在视口中把 Area2D 整体拖回篮子原本的位置（画面下方居中）即可。
  2. 转移脚本（四步）：打开现有脚本，全选复制代码；右键 Sprite2D → 选择「从脚本分离」（Detach Script，不同版本可能显示为移除脚本）；右键 Area2D →「附加脚本」，保持默认路径创建新脚本；粘贴刚才复制的代码，并将第一行改为 extends Area2D。
  3. 为该 Area2D 添加 CollisionShape2D 与 RectangleShape2D，拖出覆盖篮子的判定范围。
  4. 将篮子脚本修改为：
extends Area2D

signal died          # 自定义信号：生命耗尽时向外界通知
var score := 0
var lives := 3

func _ready() -> void:
	# 任何 Area2D 与本节点重叠时，触发 _on_pick
	area_entered.connect(_on_pick)

func _process(delta: float) -> void:
	var dir := Input.get_axis("move_left", "move_right")
	position.x += dir * 300.0 * delta
	position.x = clamp(position.x, 50, 1102)

func _on_pick(other: Area2D) -> void:
	if other.is_in_group("coin"):
		score += 1
	elif other.is_in_group("bomb"):
		lives -= 1
		if lives <= 0:
			died.emit()   # 发出信号：游戏结束
	other.queue_free()   # 被接住的对象随即销毁
	print("分数:", score, " 生命:", lives)

6.4 界面显示与游戏结束重开

  1. 在 main.tscn 中新建 CanvasLayer 节点（UI 层，始终显示在最上层），为其添加 Label 子节点，Text 填写「分数: 0」，并将 Label 拖至画面左上角。
  2. 将主脚本整体替换为以下最终版（可直接完整复制）：
extends Node2D

# preload 提前将场景文件加载进来（类似 import）
var coin_scene := preload("res://coin.tscn")
var bomb_scene := preload("res://bomb.tscn")

var game_over := false
var spawn_timer: Timer          # 计时器存为成员，游戏结束时要停下它

@onready var basket: Area2D = $Area2D            # $ 加名称 = 按路径查找子节点
@onready var ui: Label = $CanvasLayer/Label

func _ready() -> void:
	spawn_timer = Timer.new()
	spawn_timer.wait_time = 0.8
	spawn_timer.timeout.connect(_on_spawn)  # 到点发出信号，调用 _on_spawn
	add_child(spawn_timer)
	spawn_timer.start()
	basket.died.connect(_on_game_over)      # 篮子生命耗尽时收到通知

func _on_game_over() -> void:
	game_over = true
	spawn_timer.stop()   # 停止生成，画面静止，等待重开

func _on_spawn() -> void:
	# 80% 概率生成金币，20% 概率生成炸弹
	var scene := coin_scene if randf() < 0.8 else bomb_scene
	var item := scene.instantiate()  # 从模板生成一个实例
	item.position = Vector2(randf_range(60.0, 1090.0), -30)  # 屏幕上方的随机位置
	add_child(item)  # 加入场景树后，它自动开始执行自己的下落逻辑
	item.start_falling()

func _process(_delta: float) -> void:
	if game_over:
		ui.text = "游戏结束！最终分数 %d —— 按 R 重新开始" % basket.score
		if Input.is_action_just_pressed("restart"):
			get_tree().reload_current_scene()  # 重新加载场景，最简单的重开实现
		return
	ui.text = "分数: %d    生命: %d" % [basket.score, basket.lives]
  1. 按 5.2 步骤 4 的方式在输入映射中添加 restart 动作并绑定 R 键。
能够完整进行一局游戏——掉落、接取、计分、扣减生命、游戏结束（画面随之静止）、按 R 重新开始。这就是一个最小的「垂直切片」：核心玩法循环已经完整闭环。

6.5 添加音效

  1. 在 freesound.org 搜索一个金币音效与一个爆炸音效，下载 wav 文件后拖入文件面板。
  2. 回到 main.tscn，为篮子的 Area2D 添加两个 AudioStreamPlayer 子节点，分别重命名为 CoinSound 与 BombSound，在检查器的 Stream 属性槽中拖入对应的音频文件。
  3. 将篮子脚本的 _on_pick 修改为：
func _on_pick(other: Area2D) -> void:
	if other.is_in_group("coin"):
		score += 1
		$CoinSound.play()   # 播放接取音效
	elif other.is_in_group("bomb"):
		lives -= 1
		$BombSound.play()   # 播放碰撞音效
		if lives <= 0:
			died.emit()   # 发出信号：游戏结束
	other.queue_free()   # 被接住的对象随即销毁
说明：音效播放器挂在篮子上、由接取逻辑触发，而不是挂在金币上——金币被接住后会立即销毁，挂在它身上的声音也会被一并清除。新手最容易忽略的往往是音频，请记住原则：每一个游戏事件都应有对应的声音反馈（接取得分、碰撞、按钮点击等）。没有声音的游戏，体验会明显单薄。

6.6 完成之后：五项改造练习

跟完教程只是起点。以下五项练习由易到难，每完成一项，都会促使你亲手编写教程中未讲解的代码——这正是从「跟着做」到「自己做」的过渡。卡住时先查内置文档（F1），再搜索报错信息。

游戏手感第 7 章

相同的玩法规则，经过手感打磨前后带给人的体验完全不同。手感由三个因素决定：输入到反馈的延迟、运动的曲线、反馈的密度。以下是八个性价比最高的技巧，Godot 均提供内置支持。

技巧效果实现方式
压扁与拉伸跳跃时拉长、落地时压扁，角色表现立刻生动Tween 修改 scale
打击停顿命中瞬间全局暂停约 0.05 秒，显著增强打击感Engine.time_scale
屏幕震动受击或爆炸时镜头短促抖动相机 offset 加入随机偏移后恢复
拖尾残影高速移动的物体带有轨迹残像半透明 Sprite 复制 / 粒子系统
数字弹跳伤害数字弹出并向上飘散Label 与 Tween 结合
音效分层动作音与结果音分开设计AudioStreamPlayer
输入缓冲落地前约 0.1 秒内的跳跃输入依然生效，操作更顺畅计时器记录输入
土狼时间离开平台后约 0.1 秒内仍可跳跃计时器

将以下几行代码加入篮子脚本的 _on_pick（放在计分与音效逻辑之后），即可立即体验效果：

	# 接到物品时，篮子产生一次短促的弹性形变
	var tween := create_tween()
	tween.tween_property($Sprite2D, "scale", Vector2(1.3, 0.7), 0.05)
	tween.tween_property($Sprite2D, "scale", Vector2(1, 1), 0.1)
延伸学习：搜索演讲视频「Juice it or lose it」，以及游戏《Celeste》开发者在 GDC 大会上的演讲，是手感设计方向的两份经典参考。

数值设计基础第 8 章

数值设计的本质，是用数字控制玩家的情绪节奏。需要理解三条基本曲线：

成长曲线——玩家变强的成本按指数增长（例如下一等级消耗 = 当前 × 1.15），奖励同步放大。成长的满足感来自「不断变大的数字」。

难度曲线——锯齿形上升：压力逐渐增加，随后给一个释放点，然后继续增压。避免一条平坦的直线。在《接金币》中，体现为生成间隔从 0.8 秒逐渐缩短至 0.4 秒。

奖励间隔——开局前五分钟内，每 30 秒左右给予一项新内容（新敌人、新能力、新场景），此后间隔逐渐拉长。「内容丰富」的第一印象是被设计出来的。

实践原则：将所有数值集中存放（一张配置表或 Godot 的 Resource 文件），并在游戏中提供调试面板实时修改。不要为修改一个数值而重新打包整个游戏。

首要原则：风格统一比画面精美更重要。全套使用同一套免费素材，效果好于多套精美素材的拼凑。

关于音频的两点建议：背景音乐准备一首循环曲目即可（Audacity 为免费的音频剪辑工具）；音效比背景音乐更重要——每一个游戏事件都应有对应的声音反馈。

从原型到完整游戏第 10 章

完成《接金币》之后，制作自己的游戏时建议遵循以下七个阶段。每个阶段都有明确的产出标准，完成一个阶段再进入下一个。

阶段 1确定方向选定品类，撰写一句话设计，体验 10 个同类作品。约 1–2 天
阶段 2纸面原型不写代码，在纸上推演核心循环。约 1 天
阶段 3最小原型用最简单的形式让玩法可运行。约 3–7 天
阶段 4垂直切片将核心 30 秒做到好玩。约 2–4 周，最重要的阶段
阶段 5内容与数值扩充关卡、调整曲线、实现存档。约 2–4 周
阶段 6手感打磨音效、动效、反馈全面完善。约 1–2 周
阶段 7发布打包、上传平台、根据反馈迭代，见下一章

一句话设计模板：这是一个【品类】游戏，玩家通过【核心动作】获得【成长或分数】，每局时长【多长】，让人持续游玩的原因是【核心吸引力】。

适合新手的品类：超休闲（跳跃类）、放置挂机、轻量 Roguelike（单局 5 分钟）、小型塔防。共同特点：玩法单一、单局时间短、失败后可立即重开、内容依靠数值而非新机制扩展。

节奏原则：每周必须产出「可以运行的版本」。长期闭门开发、期望一次完成所有内容，是新手项目失败的最常见原因。另外，验证玩法时应先用简单的色块（白盒），确认好玩之后再替换美术素材——这样节省的是自己的时间。

打包与发布第 11 章

11.1 打包为 Windows 可执行文件

  1. 项目设置 → 显示 → 窗口：拉伸模式选择 canvas_items，宽高比选择 keep（保证在不同屏幕上显示正常）。
  2. 通过菜单栏「项目 → 导出…」打开导出面板，点击「添加」选择 Windows 桌面。首次使用会提示缺少导出模板，按引导点击「下载并安装」即可。
  3. 选择导出路径后点击导出项目，得到 catch_coin.exe，可直接分发。

11.2 打包为 Android 应用

在同样的导出面板中添加「Android」平台。首次使用需在编辑器菜单（编辑器 → 管理导出模板）中安装 Android 构建模板；若导出时提示缺少 Java 或 Android SDK，按官方文档《Exporting for Android》逐步安装即可。配置完成后可直接导出 apk 文件并安装到安卓手机，此配置只需完成一次。

11.3 发布渠道

itch.io：面向全球独立游戏的发布平台，免费上传，几分钟即可上线，适合作为第一个发布渠道。TapTap：国内的安卓游戏社区，对个人开发者友好，可免费上架。建议先让朋友与社区试玩、收集反馈并迭代，再考虑更大的平台。

制作出一个其他人无需安装 Godot 即可直接游玩的游戏。至此，「完成了一个游戏」这一目标正式达成。

常见问题第 13 章

1. 代码报错提示缩进错误怎么办？

GDScript 以缩进表示层级，全篇必须统一（全部 Tab 或全部 4 空格）。从网页复制代码时容易混入空格，全选后统一重新缩进即可。

2. 修改后没有生效？

多数情况是未保存。应养成修改后按 Ctrl+S 的习惯。

3. 可以一开始就制作开放世界 RPG 吗？

不建议。先完整实现三个小规模游戏为宜。第一款游戏的合理目标应该是「完整做出一个已被验证好玩的类型」，而非原创的大型作品。

4. 素材没有准备完成，不敢开始怎么办？

先用白盒（色块）验证玩法是否好玩，再替换正式美术。美术是放大器，不是地基。

5. 是否需要先学习 C++ 或阅读引擎源码？

不需要。GDScript 配合内置文档（F1）足以支撑很长时间的学习。引擎源码是为修改引擎的开发者准备的。

6. 什么时候可以开始学习 3D？

建议至少用 2D 完整做出一个游戏之后。2D 阶段学到的一切（循环、状态机、手感、数值）都可以直接迁移到 3D。

延伸资源

  • 官方文档（docs.godotengine.org，有中文页面）：按 F1 在编辑器内随时可查，内容比任何第三方教程权威。
  • 官方入门教程「Your first 2D game」：与本指南第 5、6 章同类型的官方实践（Dodge the Creeps），适合作为第二遍练习，见官方文档 Step by step 章节。
  • 官方问答论坛与社区（godotforums.org、Reddit 的 r/godot）：遇到报错先搜索，绝大多数问题都有人遇到过并已解答。
  • GDScript 交互式教程：编辑器内置，帮助熟悉语法细节。
